# Dua Lipa bag analysis

A prototype of the root README's roadmap idea — "own the visual signal: a
classifier over runway/street-style imagery" — scoped narrowly to one public
figure and one accessory category: what bag is she carrying, what brand does
it look like, how unconventional ("freaky") is it, and does the choice read
positively or negatively.

```
sources/serpApiImages.ts   discover candidate photos via SerpAPI Google Images
sources/seedList.ts        keyless fallback: your own curated URL list
download.ts                cache images locally (gitignored, never committed)
analyze.ts                 per-image Claude-vision call -> brand/weirdness/sentiment
aggregate.ts                pure roll-up: brand frequency, "freak index", sentiment trend
run.ts                     orchestrator
data/
  seed-urls.json           your curated list (empty by default — see below)
  sample-report.json       illustrative output, checked in so `npm run experiment:dua-lipa-bags`
                            has something to show with zero setup
  images/, report.json     generated at runtime, gitignored
```

## Running it

```bash
npm run experiment:dua-lipa-bags
```

With no `ANTHROPIC_API_KEY` set, this just prints `data/sample-report.json` —
every value in that file is invented for illustration (`example.com` URLs,
`"sample": true`), the same convention the main dashboard uses for its mock
data. It exists so you can see the output shape before wiring up keys.

To run for real you need:

- `ANTHROPIC_API_KEY` — required. Each candidate photo is one vision call to
  Claude, asked to return brand/shape/material/pattern guesses plus a
  weirdness score (0-100, "plain classic bag" to "maximally unconventional")
  and a sentiment score (0-100, same scale the dashboard uses for its overall
  Fashion Sentiment number), each with a one-line reasoning string.
- `SERPAPI_KEY` — optional. Reuses the same key the main pipeline already
  documents for Google Trends. When set, candidate photos are discovered via
  SerpAPI's `google_images` engine. When unset, the run reads
  `data/seed-urls.json` instead — a JSON array you maintain by hand:

  ```json
  [
    { "imageUrl": "https://.../photo.jpg", "sourceUrl": "https://.../article", "date": "2026-05-01" }
  ]
  ```

  `date` is optional; entries without one are excluded from the sentiment
  trend line but still counted everywhere else.

## Why SerpAPI instead of scraping directly

This deliberately calls a paid, ToS-compliant search API rather than scraping
Google Images' or Instagram's HTML — the latter would mean working around
anti-bot protections and terms of service to bulk-collect photos of a named
individual, which isn't something to build against a live target. SerpAPI (or
the curated seed list) gets the same result — discover photos already
published by press outlets — without that.

## What the analysis actually is

Brand and material calls are a vision-language model's best guess from
visible logos, hardware, and silhouette — not a verified fact, and it will
sometimes be wrong or say "unknown." Treat `brand`, `weirdness`, and
`sentiment` as descriptive commentary generated by the pipeline, not a claim
about what was actually worn or how it was actually received.

## What stays local

Downloaded image bytes live in `data/images/`, gitignored. Nothing here
redistributes the photos themselves — only the derived JSON (brand guess,
weirdness score, sentiment score, one-line captions) is meant to be committed
or shared. `sourceUrl` is always kept so any output can be traced back to the
original publication for attribution.

## Output shape

`data/report.json` matches `BagReportSummary` in `../types.ts`:
brand frequency with per-brand average weirdness, the 5 highest-weirdness
bags with their contributing traits, a sentiment trend (dated entries only),
and an overall sentiment score/label. `aggregate.ts` is pure and unit-tested
(`aggregate.test.ts`) so the roll-up math can be checked without hitting any
API.
